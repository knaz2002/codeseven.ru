# Технический долг проекта CodeSeven

## Платёжный модуль

### Текущий статус

Платёжный функционал временно отключён.

На текущей версии сайта тарифы скрыты от посетителей, а приём платежей не используется.

Платёжный обработчик дополнительно отключён на серверной стороне через переменную окружения `PAYMENT_ENABLED=false`.

Одного скрытия элементов интерфейса недостаточно, поскольку `api/payment.php` может быть вызван напрямую по HTTP.

До завершения полноценного аудита и рефакторинга значение `PAYMENT_ENABLED` должно оставаться `false`.

## Что необходимо сделать перед повторным включением оплаты

### Серверная часть

Необходимо:

- хранить перечень тарифов только на сервере;
- хранить реальные цены только на сервере;
- не доверять параметру `price`, полученному от браузера;
- отказаться от использования `$_REQUEST`;
- разделить создание платежа и проверку его статуса;
- добавить строгую серверную валидацию входных данных;
- исключить возможность подмены тарифа;
- исключить возможность подмены суммы;
- исключить создание дублирующихся заказов;
- переработать генерацию уникального номера заказа;
- корректно обрабатывать ответы платёжного API;
- добавить таймауты HTTP-запросов;
- добавить безопасное серверное логирование.

### Платёжный API

Необходимо сверить существующую интеграцию с актуальной документацией платёжного провайдера:

- формирование Token;
- обязательные параметры запросов;
- создание платежа;
- получение QR-кода;
- получение статуса платежа;
- обработка успешных, отклонённых и отменённых платежей;
- обработка повторных запросов.

### Клиентская часть

Необходимо отдельно проверить и переработать платёжную логику в `js/common.js`.

В частности:

- создание QR-кода;
- периодическую проверку статуса;
- завершение таймеров;
- обработку сетевых ошибок;
- повторную попытку оплаты;
- хранение данных в `localStorage`;
- переход после успешной или неуспешной оплаты.

### Секретные данные

Платёжные секреты должны находиться только в переменных окружения:

- `PAYMENT_TERMINAL_KEY`
- `PAYMENT_PASSWORD`

Файл `.env` запрещено добавлять в Git.

Ранее опубликованные секреты необходимо считать скомпрометированными и заменить перед повторным включением оплаты.

### Условие включения

Нельзя устанавливать `PAYMENT_ENABLED=true` до завершения аудита, рефакторинга и тестирования платёжного модуля.
